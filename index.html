01 · macOS · 2026.08 – 今

SpektraLab不模仿胶片的结果，模拟胶片的过程。

02方法Practice

人保留判断，Agent 负责执行。四个项目用的是同一个循环。

需求与测试，双重约束。

Coding Agent 让实现变便宜，判断因此更贵。我把分工写死：需求、架构取舍与验收留在我手里；实现交给 Agent，但必须同时被两样东西约束，写在前面的 PRD 与 RFC，和跑在后面的测试与基线。

  1. 01

    缺口Gap

    从真实场景里找问题，不从技术里找用途。先看用户现在拿什么凑合。

    SpektraLab：能用的不真实，真实的不能用。

  2. 02

    定义Define

    写清做什么，更写清不做什么。范围表比功能表重要。

    Bowmark：砍掉谱面识别。

  3. 03

    规格Specify

    每个技术决策一篇 RFC，先于实现；验收标准和实体关系写在里面。

    SpektraLab 30 篇，Bowmark 14 篇。

  4. 04

    实现Build

    多个 Agent 在隔离的 worktree 里并行给出方案，我评审、取舍并合并。

    Claude Code、Codex。

  5. 05

    验收Accept

    对拍参考实现、回归测试、延迟与内存基线，再加真实窗口截图。

    测试全绿，不等于用户看到的是对的。

  6. 06

    发布Ship

    打包、分发、写内容、收反馈，然后回到第一步。

    18 天，14 个版本。

领域背景，不是主线。

我 7 岁开始拍照，数码和中画幅胶片都拍，也进过暗房；在学校办过影展，讲过后期。做 SpektraLab 时，这些经验的用处不在审美，而在判断：一个结果在物理上对不对，一个参数被移动之后，应该付出什么代价。

  1. RAW 解码
  2. 光谱上采样
  3. 胶片与相纸特性曲线
  4. 颗粒与光晕
  5. 色彩管理与软打样
  6. 色域压缩
