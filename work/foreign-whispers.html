Foreign Whispers

端到端视频配音流水线 · Whisper + pyannote + Chatterbox TTS · Docker + FastAPI + Next.js

Problem

配音不只是翻译，
是五个模型的接力。

把一部外语视频变成自然的母语配音，需要转录、翻译、说话人分离、声音克隆与重混音依次协作——任何一环的误差都会级联放大。真实约束是长视频与多说话人：demo 里的 30 秒片段证明不了什么。

Definition

流水线即产品。

五段式管线：Whisper 转录 → 翻译 → pyannote 说话人分离 → Chatterbox TTS 声音克隆 → 重混音输出，整体以 Docker + FastAPI + Next.js 交付为可用产品而非脚本集合。

Process

把 85GB 的峰值内存，
降到 4GB。

长视频首先撞上的不是准确率而是内存。通过系统化复现与 Agent 协作调试定位泄漏点，将峰值内存从 85GB 压到 4GB；同期解决音频漂移与 TTS 队列冲突——这两个问题只在真实长度的素材上才会出现。

Outcome

用最难的素材验收。

以最长 39 分钟、8 位说话人、144 个语音片段的真实视频验证，说话人匹配准确率 90.5%–100%。

Retrospective

下次会不同的。

内存问题应该在第一天就有预算与监控，而不是在第 N 次崩溃后。这成为我后来所有项目的固定动作：资源预算写进规格，验收包含压力场景——Bowmark 的字节预算设计直接继承了这条教训。
